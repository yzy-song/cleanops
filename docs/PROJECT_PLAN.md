## 1. 项目章程

### 1.1 项目概述

**CleanOps** 是一个面向爱尔兰中小型清洁公司的 SaaS 运营平台。项目于 2026 年 3 月启动，已完成核心模块开发并部署至生产环境，当前处于 Beta 阶段。

### 1.2 项目目标

| 目标 | 衡量指标 | 截止日期 |
|------|------|------|
| 交付可商用 MVP | 12 个核心模块通过验收，首个付费客户上线 | 2026-06-30 |
| 验证产品市场契合 | 10 家试用公司中 ≥3 家转化为付费 | 2026-08-31 |
| 实现盈亏平衡 | MRR ≥ €500（覆盖所有运维成本） | 2026-10-31 |
| 正向现金流 | MRR ≥ €2,000 | 2026-12-31 |

### 1.3 范围定义

**本次计划覆盖范围**：从当前状态（Beta）到 v1.0 正式发布，以及 v1.1–v1.3 三个迭代。

**不在本次计划范围**：英国市场拓展、React Native 移动端 App、AI 定价引擎。上述功能在 v2.0 独立立项。

### 1.4 成功标准

- [ ] 客户可独立完成从预约到支付的完整流程，无需人工介入
- [ ] 老板可在 3 分钟内完成一周排班（当前：30 分钟+）
- [ ] 系统连续运行 30 天无 P0 故障（服务不可用 >5 分钟）
- [ ] 至少 1 家付费客户愿意提供书面推荐

- [ ] 代码通过 `pnpm build`（前后端）
- [ ] 新功能有对应的集成测试（覆盖率增量 ≥60%）
- [ ] API 端点有 Swagger 注解
- [ ] 前端文案经过 `t()` i18n 函数
- [ ] 无 console.log 残留（Hook 自动检查）
- [ ] 无硬编码密钥（Hook 自动检查）
- [ ] PR 经过 code-reviewer agent 审查

| 层级 | 覆盖范围 | 工具 | 目标覆盖率 |

| 单元测试 | 工具函数、定价引擎、VAT 计算 | Jest | ≥80% |
| 集成测试 | 核心 API（Auth, Job, Quote, Invoice） | Jest + Supertest | ≥60% |
| E2E 测试 | 预约→报价→任务→账单 主线 | Playwright | 3 条关键路径 |
| 手动验证 | UI 交互、响应式、邮件模板 | 浏览器调试 | 每个功能至少验证 1 次 |

### 7.3 性能基准

| 指标 | 目标值 | 测量方式 |
|------|------|------|
| API 列表查询响应时间 | P95 < 500ms | PM2 日志 + Artillery 压测 |
| 排班算法执行时间（1 周 × 5 工人 × 25 任务） | < 3 秒 | Console.time 计时 |
| 前端 LCP (Largest Contentful Paint) | < 2.5s | Lighthouse |
| 前端 TBT (Total Blocking Time) | < 200ms | Lighthouse |
| 服务器 CPU 使用率（空闲） | < 30% | Nezha Dashboard |
| 服务器内存使用率 | < 80% | Nezha Dashboard |

### 7.4 代码审查流程

1. 功能完成后创建 PR（分支: `feat/<功能名>`）
2. 运行 `code-reviewer` agent 审查
3. 解决所有 CRITICAL 和 HIGH 问题
4. 合并到 `main` → 自动部署到生产

## 8. 变更管理

### 8.1 范围变更流程

由于团队为单人，采用轻量级流程：

1. 新需求出现时，记录到 GitHub Issue
2. 评估工作量 + 优先级（P0/P1/P2）
3. 如果 P0 需求出现 → 替换同级 P0 或延长里程碑日期
4. 如果 P1/P2 需求 → 入 backlog，不挤占当前迭代

### 8.2 版本策略

- **主版本号** (v1.0 → v2.0): 重大架构变更或新市场
- **次版本号** (v1.1 → v1.2): 新功能模块
- **修订号** (v1.1.1 → v1.1.2): Bug 修复
